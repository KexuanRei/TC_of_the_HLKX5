- 保留原云文件ID、分享链接及可见分享权限；不会删除重建，也不会选择“保留两者”。
- 表A目前须位于“我的云文档”根目录。填写完整云端文件名，例如 `D5(1).xlsx`；另核对配置的原分享链接，名称相同但链接不符时中止。
- 保留表C全部工作表及名称、行高列宽、合并、图片、单元格样式和条件格式。扫描范围、粘贴批次、首轮格式模式和旧筛选配置不再参与主同步流程。
- 公式仅使用下载文件中保存的计算结果，不在本地重新计算。缺失缓存会停止上传；源表已有错误结果原样保留并计数。
- 原表C保存在 `DATA/表C.xlsx`；覆盖前备份在 `DATA/HSTY/`（最多15份）；上传文件及回读文件在 `DATA/UPLOAD/`（最近3次已核验包）。
- 覆盖后下载的XLSX逐成员核对内容；ZIP压缩方式和时间戳可不同，解压后的成员内容必须全部相同。**先比内容成员（`xl/*`、`[Content_Types].xml` 等），再比 `docProps/*` 元数据**——报错直指真正的内容差异（如 `xl/sharedStrings.xml`、`xl/worksheets/sheet1.xml`），不会被时间戳元数据掩盖。WPS如果重写文件内容，本轮会报告未确认成功，不会降低为抽查。
- 文件上传完成前不会刷新或关闭页面。**上传被取消/失败（含任何上传异常）会自动清除 `cloud_upload_pending.json` 待核验记录，下一轮自动重新上传**（文件没离开本机，不会陷入「只回读核验、不再上传」的死循环）。覆盖后核验按 10/20/40/80/120/150 秒退避重试约 7 分钟（每次重新下载云端文件核对）；重试后仍不一致时与覆盖前备份比对——云端仍为覆盖前版本则自动清除待核验状态、下一轮重新上传覆盖，云端被他人修改则保留备份与待核验状态、失败关闭并提示人工处理。确认恢复完成前不要手动删除待核验文件。
- 停止任务不能撤回已经提交到云端的覆盖；可以用本地备份或云端历史版本恢复。
- 更新后重新运行 `start_ui.bat`，网页按 Ctrl+F5；前后台版本号必须一致。程序自有Edge需登录金山文档。

# 表C → 表A 整表同步

在线表C是变化来源，在线表A是写入目标。每轮先下载表C整表文件到 `DATA/表C.xlsx`（数据与格式的唯一来源），首轮先分批粘贴整表格式，再清空旧内容并分批粘贴纯数据，最终逐格回读校验；后续轮次仅执行数据阶段。**启动定时任务后的第一轮先整表粘贴格式，再整表粘贴纯数据，之后所有轮次只粘贴数据**，表A已有格式保持不变。不再使用中间镜像（表A1）、不再按主键比对、不再只贴差异单元格；不依赖数据库服务。

## 使用

1. 运行 `安装依赖.bat`，再运行 `start_ui.bat`。
2. 在工作台填写表C、表A的分享链接、工作表名称和扫描范围（选填，留空自动整表），打开专用Edge并登录。
3. 设置数据起始行、每批行数、等待时间并保存，启动定时任务。
4. 需要时使用「手动下载表C」（下载成功后自动接着整表上传）、「手动下载表A快照」按钮。

## 首次与后续流程

- **每轮同步**：下载表C整表到 `DATA/表C.xlsx` →（若开启表B快照）先存一份表A历史快照 → 首轮先整表粘贴格式 → 清空表A旧内容（保留格式）→ 分批粘贴纯数据 → 回读校验；后续只执行数据阶段。
- **首次与后续一致**：整表模式没有「基线」与「增量」之分，每轮都是整表覆盖，表A内容始终等于当次下载的表C全表。
- **格式粘贴只在第一轮**：启动定时任务后的第一轮先整表粘贴格式，再整表粘贴纯数据（格式预检失败会中止本轮、绝不无格式粘贴，失败后下一轮自动重试）；之后所有轮次只粘贴数据，表A已有格式保持不变。需要重新粘贴格式时，停止后再启动定时任务。
- **手动下载表C**：下载成功后自动接着整表上传（不粘贴格式；格式只随定时任务的第一轮粘贴）。
- **失败恢复**：中断只影响当前轮次；下次从头重新下载表C并整表覆盖，整表覆盖天然幂等。
- **改动即同步**：整表模式下也直接整表上传，不再只同步变动行。

表C列范围取扫描区域的右边界（若填写），否则取文件实际最大列；行范围取文件实际最大行。带格式轮复制所选范围全部行的单元格格式（包括表头）；「数据起始行」不再让整表模式的前几行丢失格式。

## 数据规则

- 整表覆盖从 A1 起：首轮先完成整表格式阶段，再清空旧内容（含隐藏的遗留行，保留格式）并分批粘贴值；格式与数据两阶段都按配置上限取最大整行数（默认 8 万格；80 列时 1000 行），最后一批取余数。HTML 超过 64 MiB 时继续拆小。逐批回读校验，校验通过才继续下一批。
- 保留单元格格式（仅第一轮）：数字/日期格式、字体、填充、边框、对齐，全部取自表C自身。公式只取计算结果、不粘贴公式本身。不套用行高/列宽/合并单元格。
- 带格式轮：数值/日期经剪贴板 `x:num` + `mso-number-format` 写入，保持数值/日期格式、不退化成文本；文本用 `x:str`，前导零保持原样。
- 纯数据阶段及后续轮次：明确选择 WPS“粘贴值”，载荷只含 `x:str` / `x:num` 类型信息、不含任何 CSS（包括数字格式），沿用目标格式。形似日期的文本由首轮建立的文本格式和回读校验保护；后续若新增行没有适当格式而发生转换，会报告失败。需要给新行补格式时，停止后再启动定时任务。菜单无法确认时直接报错，不静默改用普通粘贴。
- 下载文件用「同目录临时文件 + 原子替换」，失败保留旧文件。

## 表B 历史快照

- 表B 不再参与差异对比，仅作为「表A历史快照」留存。
- 默认关闭自动快照（配置 `sync.table_b_snapshot`，默认 false）；开启后每轮上传前先把表A另存为一份快照。
- 也可点「手动下载表A快照」立即存一份。
- 快照保存在 `DATA/HSTY/表A_YYYYMMDD_HHMMSS.xlsx`，最多保留 15 份，超出自动删除最早的一份。

## 发现更新

整表模式每轮都把表C整表覆盖到表A，他人对表C的修改会在下一轮整表上传时进入表A。专用Edge中开启「即时同步」时，本机编辑表C会触发一次整表上传（防抖后）；他人从其他设备编辑表C，由定时轮次整表覆盖发现。

停止按钮取消后续轮次，并在下一检查点中断当前轮次；整表覆盖幂等，已粘贴的部分不单独恢复，下次从头整表覆盖。

## 操作日志

「操作记录」开关默认开启，本地运行的全部操作写入 `LOG/`（每天一个 `LOG/YYYY-MM-DD.log`，自动保留最近 90 天，敏感信息脱敏）：

- **表C**：打开工作表、下载（路径/工作表/大小/耗时）、读取本地表C 文件（行列数）、在线选择/复制单元格、检测到改动；
- **表A**：打开工作表、清空已用区域、选择/复制/粘贴单元格（区域、粘贴内容、耗时）、逐批回读校验、整表上传统计；
- **表B（表A历史快照）**：开始/完成下载快照、保存快照（路径/大小）、轮换删除旧快照；
- **任务**：网页服务启动、保存配置（全部关键字段）、任务排队、定时任务启动/停止、同步完成/失败（含统计）、打开表C/表A 成功与失败。

关闭该开关后不再产生任何日志文件。

## 磁盘占用与清理

专用 Edge 的配置目录 `edge_copy_profile` 会随使用不断累积浏览器缓存（此前曾增长到近 700 MB），`prepare_env.bat` 重建环境时也会留下 `.venv_old_*` 备份。

关闭 `start_ui.bat` 服务窗口和专用 Edge 后，双击 `清理占用空间.bat` 可安全删除这些可再生内容（浏览器缓存、旧虚拟环境备份、`__pycache__`、过大的差异诊断日志）。登录状态（`Local State`、`Network\Cookies`、`Local Storage` 等）、`.venv`、`DATA\`、同步进度和源码都不会被改动；清空缓存后首次打开在线表格会略慢，不需要重新登录。程序运行期间脚本会检测到并拒绝执行。

## 2026-11-04 格式完整性修复

带格式轮逐格校验内容、字体、填充、边框、对齐和数字格式。发现缺失时先等待并重新读取，仍不一致就缩小范围补贴（最多三层）；未通过则明确报错并保留下一轮带格式重试状态。粘贴前先选择落点，再写入并核对系统剪贴板，避免选择期间内容被替换。

更新后重启 `start_ui.bat` 对应的 Python 服务，在工作台停止再启动定时任务，重新执行带格式的第一轮；仅点击手动下载表C仍是仅数据流程。带格式轮比原先耗时更长。

## 2026-11-04 两阶段与最大行数

仅启动后的第一轮：先完成全部“粘贴格式”批次，再清空旧内容并完成全部“粘贴值”批次。两阶段都使用 `floor(upload.batch_cells / 实际列数)` 行；当前 80000 格 / 80 列 = 1000 行。只有实际载荷超限或回读不一致才缩小范围。

格式阶段遇到空白区域且没有真实格式回读时，标记为待最终复核；第二阶段逐格校验数据和格式，任一项不一致都不会报告成功。后续轮次仅更新数据。菜单识别及真实 WPS 粘贴效果仍须在线运行验证。
